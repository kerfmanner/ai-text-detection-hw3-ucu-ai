`# scope.md — UCU AI 2026, Homework 3: Human / AI / Fusion Text Classification

This file sets what the project must deliver and what is not allowed. It deliberately names no models, libraries, features or techniques.
If a task is not covered here, or it conflicts with this file, stop and ask the human owner.

## 1. Objective

Classify each text as one of:

| label    | meaning                                  |
|----------|------------------------------------------|
| `human`  | written by a human                       |
| `ai`     | generated by an LLM                      |
| `fusion` | a human text partly rewritten by an LLM  |

- Languages: English (`en-EN`) and German (`de-DE`).
- Domains: news, arXiv papers, blogs, UK parliament, German parliament, court cases, student essays, books.
- **Metric: macro-F1 over the three classes**, computed with `sklearn.metrics.f1_score(y_true, y_pred, average="macro")`. Every class counts the same.
- Deadline: the competition closes around **2026-11-23**.

## 2. Data

| file                    | rows    | columns                                   |
|-------------------------|---------|-------------------------------------------|
| `train.csv`             | 272,352 | `id`, `text`, `lang`, `domain`, `label`   |
| `test.csv`              | 25,000  | `id`, `text`, `lang`, `domain`            |
| `sample_submission.csv` | 25,000  | `id`, `label` (format and row order only) |

- Texts are 20–3000 words long, with a median of 463.
- Source: a processed subset of GhostWriter (Schaaf, Bönisch & Mehler, LREC 2026). License: CC BY-NC-SA 4.0, for course use only.
- A human text and its `ai`/`fusion` versions are always on the same side of the train/test split. There is no group-id column.

## 3. Required deliverables

### 3.1 Fixed validation split
- One fixed validation split taken from `train.csv`, reproducible and saved to disk, used for **every** comparison.
- It must not leak related versions of the same source text across train and validation (see §2). The agent decides how to detect and handle this, and documents the method and its limits.
- Every model reports macro-F1 and per-class metrics on this split.

### 3.2 EDA
For example it could cover:
- class balance by language and by domain
- text lengths
- examples of each class, short and truncated, chosen by code
- what makes `fusion` different from the other classes
- how these findings shaped the modelling choices

### 3.3 Baseline
- A vectorizer-based feature representation with classical ML models.
- A small parameter search.
- Per-class metrics and a confusion matrix.

### 3.4 Encoder
- A fine-tuned multilingual transformer.
- Explicit handling of texts longer than the model's maximum input length.
- A comparison with the baseline on the same validation split.

### 3.5 Further experiments
- At least two more experiments. The agent picks them and writes down the motivation for each.
- Each one is compared against a single fixed reference model, chosen and frozen beforehand, on the same validation split.
- Experiments that fail are still logged, with the reason they failed.

### 3.6 Final model and submission
- The final model is selected by validation macro-F1.
- `submission.csv`:
  - exactly two columns, `id` and `label`
  - all 25,000 test ids, each exactly once
  - lowercase labels only: `human`, `ai`, `fusion`
  - same row order as `sample_submission.csv` (align by `id` before saving)
  - no index and no extra columns
- An automated check confirms all of the above before any upload.

### 3.7 Explainability (optional)
- Explain what the final model relies on and draw conclusions from it. The agent chooses the method.

### 3.8 Reproducibility
- Run instructions for every stage, from the split to the final prediction.
- Pinned dependencies, fixed seeds and saved configs.
- An experiment log with, for each experiment: id, reference model, what changed, validation macro-F1, per-class F1, notes.
- A citations file listing every external code snippet, tutorial, paper or idea used.

## 4. Out of scope

- **Writing the report.** AI tools may not write it. Agents may hand over raw material (tables, figures, logs, metrics) but no report prose.
- Work that isn't about this classification task: deployment, apps, APIs, dashboards.
- Leaderboard probing: selecting models by public-leaderboard score instead of internal validation.

---

## 5. Prohibited (hard rules)

1. **No proprietary LLMs on the data.** Closed models (via API or chat) must not label, generate, rewrite, augment or extract features from any train or test text.
   This includes the agent itself: it must not read texts and label, judge or annotate them. All analysis of the data goes through code and open-weight models. Open-weight models are allowed.
2. **No external data.** Train on `train.csv` only. Do not use the original dataset or any other external source to look up or improve predictions. Pretrained weights are allowed.
3. **No data leakage**, including:
   - fitting any transformation, statistic, vocabulary or feature selection on validation or test rows
   - tuning on test rows, or using test labels in any form
   - fitting any second-level model (stacking, calibration, thresholds) on the same predictions it is evaluated on
4. **No fitting on test texts** in any form: no self-training, and no use of structure among test rows. Explicit written approval from the human owner is needed first.
5. **Independent work.** Do not copy code from other course participants or from public solutions to this homework. Cite every external source.
6. Respect the dataset license. Do not publish or upload the data.

---

## 6. Code and output standards

- Structured, reusable code. The agent decides the layout and documents it in the STRUCTURE.md.
- No long unfiltered printouts. Verbose output goes to log files.
- All notebooks and scripts run top to bottom without errors.
- One metric implementation, one validation split and one label mapping, shared across all experiments.
- Saved model outputs, so later comparisons or combinations don't need retraining.
- Compute assumptions and training settings are recorded for each run.`
